# Contributing to Techanv Consulting

Thank you for your interest in contributing. We welcome contributions from the community across all our open-source projects.

## How to Contribute

### 1. Reporting Issues

- Search existing issues before opening a new one
- Use the appropriate issue template if available
- Include steps to reproduce, expected behavior, and actual behavior
- Attach logs, screenshots, or error messages where relevant

### 2. Reporting Security Vulnerabilities

**Do not open a public issue for security vulnerabilities.**

Email us directly at [contact@techanv.com](mailto:contact@techanv.com) with:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested fix (optional)

We will respond within 48 hours and coordinate a responsible disclosure timeline.

### 3. Submitting Pull Requests

1. Fork the repository and create a branch from `main`
2. Name your branch descriptively: `feat/add-scanner`, `fix/auth-bypass`, `docs/update-readme`
3. Make focused, atomic commits — one logical change per commit
4. Write clear commit messages: what changed and why
5. Ensure your changes do not break existing tests
6. Open a pull request against `main` with a clear description

### 4. Code Standards

- Follow the language/framework conventions already in the repo
- Write self-documenting code — avoid unnecessary comments
- Do not introduce dependencies without discussion
- Security-sensitive code must be reviewed by a maintainer before merge

### 5. Documentation

- Update relevant docs alongside code changes
- Keep READMEs accurate and concise

## Community Standards

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions?

Reach us at [contact@techanv.com](mailto:contact@techanv.com) or open a discussion in the relevant repository.
